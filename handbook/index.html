§7.1.1NULL and Three-Valued Logic

NULL 與三值邏輯

如果櫃檯還沒填房價，這間房能通過「超過 200」的條件嗎？

SQL
-- 自編三筆房價，最後一間的價格尚未登記
WITH SampleRoom(room_id, price) AS (
    VALUES ('A', 247), ('B', 150), ('C', NULL)
)
SELECT room_id, price
FROM SampleRoom
WHERE price > 200;  -- 只留下條件為 TRUE 的列

按順序讀這段查詢

  1. A 的 247 > 200 為 TRUE，留下。B 的 150 > 200 為 FALSE，排除。
  2. C 的房價未知，NULL > 200 的結果也是 UNKNOWN。WHERE 只保留 TRUE，所以看不到 C。
  3. 若改為 WHERE price IS NULL，答案只有 C。IS NOT NULL 則留下 A、B。

查詢結果 · 1 列

room_idprice
A247
筆記簡寫WHERE 只留 TRUE；查缺值用 IS NULL。
三值邏輯怎麼推？

NULL 可以代表未知、未提供或不適用。TRUE AND UNKNOWN 是 UNKNOWN，FALSE AND UNKNOWN 是 FALSE。TRUE OR UNKNOWN 是 TRUE，FALSE OR UNKNOWN 是 UNKNOWN。NOT UNKNOWN 仍是 UNKNOWN。

§7.1.2Nested Queries, Tuples, and Set/Multiset Comparisons

巢狀查詢與集合比較

哪些顧客訂過 H001 的房間？先找訂房者編號，再查姓名。

SQL
SELECT c.cust_id, c.name
FROM Customer AS c
WHERE c.cust_id IN (                 -- 目前顧客在名單裡嗎？
    SELECT b.cust_id
    FROM Booking AS b
    JOIN Room AS r ON r.room_id = b.room_id
    WHERE r.hotel_id = 'H001'
)
ORDER BY c.cust_id;

按順序讀這段查詢

  1. 括號裡先按房間編號配對，找出 H001 的訂房者 C015、C035。這個子查詢可以獨立讀。
  2. 外層掃顧客表，一位顧客的編號只要等於名單中任一值，就輸出該顧客。名單裡重複的編號不會讓外層多印一列。

查詢結果 · 2 列

cust_idname
C015Linet Morrieson
C035Suzanna Hartrick
筆記簡寫IN 找相等；ANY 至少一個；ALL 每一個。
ANY、ALL 與多欄比對

假設子查詢傳回 100、200。150 > ANY（子查詢）為真，因為 150 > 100；150 > ALL（子查詢）為假，因為 150 < 200。SOME 與 ANY 同義，= ANY 等同 IN。比對 (cust_id, room_id) 時，兩個值要在內層的同一列同時對上。

§7.1.3Correlated Nested Queries

相關子查詢

找出 H001、H002 各自最貴的房間。外層換飯店，內層比價的範圍也跟著換。

SQL
SELECT h.hotel_id, r.room_id, r.price
FROM Hotel AS h
JOIN Room AS r ON r.hotel_id = h.hotel_id
WHERE h.hotel_id IN ('H001', 'H002')
  AND r.price = (
      SELECT MAX(r2.price) FROM Room AS r2
      WHERE r2.hotel_id = h.hotel_id  -- 內層引用外層的 h
  )
ORDER BY h.hotel_id, r.room_id;

按順序讀這段查詢

  1. h 是外層目前的飯店，r 是目前拿來檢查的房間。r2 讓內層再讀一次 Room；每一列仍有自己的 room_id。
  2. 外層看到 H002 時，把 h.hotel_id 代成 H002。內層把 102、152、110 拿來比，傳回 152。
  3. 回到外層，只有 r.price = 152 的 R0202 通過。H001 則從 97、150、247 算出 247。若有兩間並列最貴，兩間都符合。

查詢結果 · 2 列

hotel_idroom_idprice
H001R0103247
H002R0202152
筆記簡寫外層給飯店編號，內層只比這家的房價，外層再判斷。
回到原卷 Q2

模擬卷 Q2 再用訂房紀錄、顧客國家和星等篩選。即使某間通過最高價條件，仍須有人訂過且符合其他條件，才會出現在 Q2。

§7.1.4EXISTS, NOT EXISTS, and UNIQUE

有沒有紀錄？

模擬卷 Q3 查的是「哪些飯店有台灣顧客訂過」。只要找到一筆，這家飯店就入選。

SQL
SELECT h.hotel_id, h.name
FROM Hotel AS h
WHERE EXISTS (
    SELECT 1                          -- 只檢查是否有資料列
    FROM Room AS r
    JOIN Booking AS b ON b.room_id = r.room_id
    JOIN Customer AS c ON c.cust_id = b.cust_id
    WHERE r.hotel_id = h.hotel_id      -- 目前這家飯店
      AND c.country = 'Taiwan'
)
ORDER BY h.hotel_id;

按順序讀這段查詢

  1. 查 H001 時，R0101 屬於這家飯店。訂房 B013 對應顧客 C035，國家是 Taiwan，所以 EXISTS 成立。
  2. 外層一列代表一家飯店。就算找到三筆符合的訂房，這家飯店也只輸出一次。這裡加了 ORDER BY，方便核對。
  3. 改用 NOT EXISTS 就找零筆符合訂房的飯店，包括完全沒有訂房的飯店。

查詢結果 · 5 列

hotel_idname
H001Emerald Bay Hotel
H003Blue Horizon Inn
H005Crystal Sky Hotel
H007Royal Garden Hotel
H009Sunrise Harbor Resort
筆記簡寫EXISTS 看有沒有列；NOT EXISTS 要零列；UNIQUE 看結果列有沒有重複。
UNIQUE 與雙重 NOT EXISTS

課本的 UNIQUE(子查詢) 在結果沒有重複列時為真，實際支援依資料庫而異。遇到雙重 NOT EXISTS，可讀成「找不到任何一個缺漏」。例如「沒有任何一間 H001 房間，是這位顧客沒訂過的」就等於每間都訂過。

§7.1.5Explicit Sets and Renaming

明列集合與取別名

列出 H001 和 H002 的飯店名稱，讓答案表的標題清楚寫成 hotel_name。

SQL
SELECT h.hotel_id, h.name AS hotel_name  -- 結果欄位名稱
FROM Hotel AS h                          -- Hotel 的簡稱
WHERE h.hotel_id IN ('H001', 'H002')      -- 直接列出接受的值
ORDER BY h.hotel_id;

按順序讀這段查詢

  1. FROM Hotel AS h 讓 h 指向 Hotel。h.name 就是當前飯店那一列的 name。
  2. IN 括號內列出兩個飯店編號。只要等於其中一個就留下。Q2 的國家清單 IN ('Japan', 'Taiwan') 同理。
  3. SELECT 裡的 AS 改顯示欄名。答案表標題叫 hotel_name，底下的值仍是原來的飯店名字。

查詢結果 · 2 列

hotel_idhotel_name
H001Emerald Bay Hotel
H002Golden Lotus Resort
筆記簡寫FROM 裡的 AS 幫資料表取簡稱；SELECT 裡的 AS 幫輸出欄位取名。
同一張表可以有兩個名字嗎？

同一張表可以用不同別名扮演不同角色。§7.1.3 的 r 是要檢查的房間，r2 是內層用來比價的房間。

§7.1.6Joined Tables and Outer Joins

連接與外部連接

比較有兩筆訂房的 C015 和零筆訂房的 C024，觀察誰會留在答案裡。

SQL
SELECT c.cust_id, b.book_id
FROM Customer AS c
LEFT JOIN Booking AS b              -- 保留左邊的顧客
    ON c.cust_id = b.cust_id        -- 依顧客編號配對
WHERE c.cust_id IN ('C015', 'C024')
ORDER BY c.cust_id, b.book_id;

按順序讀這段查詢

  1. 從左邊的 Customer 拿到 C015，去 Booking 找到 B002、B006。配到兩筆就產生兩列。
  2. C024 找不到相符訂單。LEFT JOIN 仍保留顧客那列，右邊的 b.book_id 補 NULL。
  3. 改成 JOIN（INNER JOIN）時只留下配對成功的兩列，C024 消失。Q4 用 LEFT JOIN，才能讓零次訂房也顯示。

查詢結果 · 3 列

cust_idbook_id
C015B002
C015B006
C024NULL
筆記簡寫ON 決定怎麼配對；LEFT JOIN 讓左邊每列至少出現一次。
其他 JOIN 與篩選條件

RIGHT JOIN 保留右側未配對列，FULL OUTER JOIN 兩側都保留。NATURAL JOIN 自動比對所有同名欄，合併同名欄位。指定 ON 可以清楚寫出配對規則。外部連接後若用 WHERE 要求右側欄位等於某個值，右側補 NULL 的列可能又被篩掉。

§7.1.7Aggregate Functions

聚合函數

H002 有幾間房？房價的總和、平均、最低和最高各是多少？

SQL
SELECT COUNT(*) AS rooms,          -- 數列
       SUM(price) AS total,
       ROUND(AVG(price), 2) AS mean_price,
       MIN(price) AS lowest,
       MAX(price) AS highest
FROM Room
WHERE hotel_id = 'H002';

按順序讀這段查詢

  1. 先篩到 H002 的三列，房價分別是 102、152、110。
  2. COUNT(*) 數到 3；SUM 是 364。平均用 364 ÷ 3，ROUND 將顯示值四捨五入到小數點後兩位。
  3. 回看前一節的 C024：LEFT JOIN 保留一列。對那一組而言 COUNT(*) = 1，COUNT(b.book_id) = 0，因為該欄是 NULL。

查詢結果 · 1 列

roomstotalmean_pricelowesthighest
3364121.33102152
筆記簡寫COUNT(*) 數列；COUNT(欄位) 數非 NULL；COUNT(DISTINCT 欄位) 去重再數。
空值與重複值怎麼算？

若 C015 有兩筆訂房，COUNT(b.cust_id) 仍數到 2；COUNT(DISTINCT b.cust_id) 只數到 1。SUM、AVG、MIN、MAX 都會略過 NULL。若沒有可計算的值，這四種函數傳回 NULL，COUNT 傳回 0。

§7.1.8Grouping: GROUP BY and HAVING

分組與群組篩選

在 C015、C020、C024 裡，找出至少訂過兩次房的人。

SQL
SELECT c.cust_id, COUNT(b.book_id) AS booking_count
FROM Customer AS c
LEFT JOIN Booking AS b ON b.cust_id = c.cust_id
WHERE c.cust_id IN ('C015', 'C020', 'C024')
GROUP BY c.cust_id                 -- 同一位顧客放一組
HAVING COUNT(b.book_id) >= 2       -- 算完以後篩整組
ORDER BY c.cust_id;

按順序讀這段查詢

  1. WHERE 先保留這三位顧客的列。C015 對應 B002、B006，C020 對應 B012，C024 對應 NULL。
  2. GROUP BY 得到三組，各組訂房數分別為 2、1、0。HAVING 只留筆數至少 2 的組。
  3. COUNT 寫兩次有兩個用途：HAVING 決定誰留下，SELECT 把次數印在答案表。如果拿掉 HAVING，三個人都會顯示。

查詢結果 · 1 列

cust_idbooking_count
C0152
筆記簡寫WHERE 篩列，GROUP BY 分組，HAVING 篩組。
改數 b.cust_id 會怎樣？

本例把 HAVING 的 b.book_id 換成 b.cust_id，結果相同：每筆成功配對都有顧客編號，沒配到時右側補 NULL。考題若改數左側 c.cust_id，要留意左側編號仍有值。

§7.1.9Other SQL Constructs: WITH and CASE

替查詢命名，替結果分類

先算三位顧客各訂了幾次，再替每人加上一欄好讀的文字。

SQL
WITH BookingCounts AS (              -- 此查詢內可用的結果名稱
    SELECT c.cust_id, COUNT(b.book_id) AS booking_count
    FROM Customer AS c
    LEFT JOIN Booking AS b ON b.cust_id = c.cust_id
    WHERE c.cust_id IN ('C015', 'C020', 'C024')
    GROUP BY c.cust_id
)
SELECT cust_id, booking_count,
       CASE WHEN booking_count >= 2 THEN '至少兩次'
            WHEN booking_count = 1 THEN '一次'
            ELSE '尚未訂房'
       END AS booking_status
FROM BookingCounts
ORDER BY cust_id;

按順序讀這段查詢

  1. WITH 後面括號裡的 SELECT 先提供一張兩欄的查詢結果，名叫 BookingCounts。這個名字的使用範圍是這一個 SQL 敘述。
  2. 主查詢從 BookingCounts 取資料。CASE 由上往下檢查 WHEN，採用第一個成立的 THEN。全部不成立時用 ELSE。
  3. C024 的次數是 0，走到 ELSE，顯示「尚未訂房」。三位顧客都還在結果裡。

查詢結果 · 3 列

cust_idbooking_countbooking_status
C0152至少兩次
C0201一次
C0240尚未訂房
筆記簡寫WITH 幫中間結果命名；CASE 依條件產生欄值。
CASE 和 HAVING 的作用

回顧 §7.1.8：HAVING COUNT(...) >= 2 會把整組排除。這裡把條件寫在 SELECT 的 CASE，只決定 booking_status 的文字。

§7.1.10Recursive Queries in SQL

逐層找出推薦名單

模擬卷 Q4 從 C035 出發，列出直接和間接推薦的人、距離幾層，以及每人訂房幾次。

SQL
WITH RECURSIVE ReferralTree (cust_id, referral_depth) AS (
    -- 起點：C035 直接推薦的人，深度是 1
    SELECT referred_id, 1
    FROM CustomerReferral
    WHERE referrer_id = 'C035'
    UNION ALL
    -- 往下一層：把剛找到的顧客當作推薦人
    SELECT r.referred_id, t.referral_depth + 1
    FROM CustomerReferral AS r
    JOIN ReferralTree AS t ON r.referrer_id = t.cust_id
)
SELECT t.cust_id, c.name AS customer_name,
       t.referral_depth, COUNT(b.book_id) AS booking_count
FROM ReferralTree AS t
JOIN Customer AS c ON c.cust_id = t.cust_id
LEFT JOIN Booking AS b ON b.cust_id = t.cust_id
GROUP BY t.cust_id, c.name, t.referral_depth
ORDER BY t.referral_depth, t.cust_id;

按順序讀這段查詢

  1. 先認欄位：referrer_id 是推薦別人的人，referred_id 是被推薦的人。起始查詢只取 C035 的直接被推薦者，所以 C035 本人不在答案裡。
  2. 第一層是 C002、C015、C024。下一輪把這三人當推薦人：C015 推薦了 C036，C024 推薦了 C040，所以 C036、C040 是第二層。
  3. 第三層是 C040 推薦的 C029。C029 沒有再推薦人，下一輪產生零列，遞迴結束。UNION ALL 保留每輪產生的列。
  4. 最後才接姓名和訂房。C024 推薦過別人，但自己訂房 0 次。LEFT JOIN 把他留下，COUNT(b.book_id) 得到 0。

查詢結果 · 6 列

C024Gardner Forker10

遞迴什麼時候停？

本卷推薦資料沒有循環；實務若允許繞回先前的人，使用 UNION ALL 時要設防循環條件。ORDER BY 先依層數，再依顧客編號排序。

§7.1.11Discussion and Summary of SQL Queries

把一段查詢讀成一句話

綜合第七章前段：找出台灣顧客中訂房至少兩次的人，依訂房數由多至少排列。

SQL
SELECT c.cust_id, c.name, COUNT(b.book_id) AS booking_count
FROM Customer AS c
JOIN Booking AS b ON c.cust_id = b.cust_id
WHERE c.country = 'Taiwan'           -- 先留下台灣顧客的列
GROUP BY c.cust_id, c.name           -- 每位顧客各算各的
HAVING COUNT(b.book_id) >= 2         -- 保留達到門檻的人
ORDER BY booking_count DESC, c.cust_id ASC;

按順序讀這段查詢

  1. 紙上先讀 FROM / JOIN：用 cust_id 對上顧客與訂房。一列代表一筆成功配到的訂房。
  2. WHERE 先看列的國家。GROUP BY 聚成每人一組，HAVING 只留至少兩筆的組。
  3. SELECT 決定最後要填哪三欄。ORDER BY 控制呈現順序；筆數相同時按顧客編號升冪。這是手算的邏輯順序，資料庫可以用不同的實體執行計畫。

查詢結果 · 1 列

cust_idnamebooking_count
C035Suzanna Hartrick3
筆記簡寫手算順序：FROM / JOIN → WHERE → GROUP BY → HAVING → SELECT → ORDER BY。
排序與去除重複

讀到 SELECT DISTINCT 時，對輸出欄位的整列去重。SQL 題若沒有 ORDER BY，查詢本身不保證輸出順序。模擬卷 Q1 要按房價 DESC，Q2 則用 ASC。

Q4　推薦層級與訂房次數

第一層從 C035 的直接推薦對象開始。結果列按層級和顧客編號排列。

SQL
WITH RECURSIVE ReferralTree (cust_id, referral_depth) AS (
   SELECT referred_id, 1
   FROM CustomerReferral
   WHERE referrer_id = 'C035'

     UNION ALL

     SELECT r.referred_id, t.referral_depth + 1
     FROM CustomerReferral AS r
     JOIN ReferralTree AS t ON r.referrer_id = t.cust_id
)
SELECT t.cust_id, c.name AS customer_name,
      t.referral_depth, COUNT(b.book_id) AS booking_count
FROM ReferralTree AS t
JOIN Customer AS c ON c.cust_id = t.cust_id
LEFT JOIN Booking AS b ON b.cust_id = t.cust_id
GROUP BY t.cust_id, c.name, t.referral_depth
ORDER BY t.referral_depth, t.cust_id;
